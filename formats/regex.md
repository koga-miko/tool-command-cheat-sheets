# Regex (正規表現) Cheat Sheet

## Overview

正規表現（Regular Expression）は、文字列のパターンマッチングを表現するためのミニ言語です。`grep`/`rg`/`sed`/`awk` や各種プログラミング言語の文字列処理など、あらゆる場所で共通して使われます。実務ではログの抽出、バリデーション、置換対象の指定などで頻繁に使います。

## When to Use

- ログや大量のテキストから特定パターンだけを抜き出したいとき
- メールアドレスや電話番号など、入力値の形式をチェックしたいとき
- 文字列の一部だけを狙って置換したいとき（[rg](../commands/rg.md)/`sed`/エディタの検索置換など）

## Basic Syntax

```text
/pattern/flags     # JavaScript, sed, Perl などでよく使う記法
pattern            # grep, rg, Python re.compile() など、記号なしでそのまま渡す処理系も多い
```

## Common Examples

```regex
# 任意の1文字（改行にはマッチしないのが既定）
.

# 直前の要素の0回以上の繰り返し（貪欲）
a*

# 直前の要素の1回以上の繰り返し
a+

# 直前の要素が0回または1回（あってもなくても良い）
a?

# 繰り返し回数を指定
a{2,4}    # 2〜4回
a{3}      # ちょうど3回
a{2,}     # 2回以上

# 文字クラス
[abc]     # a, b, c のいずれか1文字
[^abc]    # a, b, c 以外の1文字
[a-z0-9]  # 範囲指定

# よく使う省略記法
\d  # 数字 [0-9]
\w  # 単語構成文字 [a-zA-Z0-9_]
\s  # 空白文字（スペース・タブ・改行など）
\D \W \S  # それぞれの否定

# グループ化と選択（OR）
(cat|dog)

# メールアドレスっぽいパターンの抽出例
[\w.+-]+@[\w-]+\.[a-zA-Z]{2,}
```

## Frequently Used Options

```regex
# --- アンカー（文字を消費せず、位置にマッチする） ---
^abc      # 行頭
abc$      # 行末
\babc\b   # 単語境界（wordの前後という「位置」にマッチ、文字は消費しない）
\B        # 単語境界でない位置

# --- 先読み・後読み（lookaround） ---
# マッチ範囲・キャプチャ結果には含まれず、文字列も消費しない「ゼロ幅アサーション」
foo(?=bar)      # 直後に bar が続く foo にマッチ（肯定先読み / lookahead）
foo(?!bar)      # 直後に bar が続かない foo にマッチ（否定先読み / negative lookahead）
(?<=foo)bar     # 直前が foo である bar にマッチ（肯定後読み / lookbehind）
(?<!foo)bar     # 直前が foo でない bar にマッチ（否定後読み / negative lookbehind）

# 例: "100円" から単位を消費せずに数値だけを取り出す
\d+(?=円)

# 例: 先頭に $ が付いていない数値だけを拾う
(?<!\$)\d+

# --- 貪欲 / 非貪欲 ---
".*"      # 貪欲（最長一致）: 最初の " から最後の " までマッチしてしまう
".*?"     # 非貪欲（最短一致）: * や + の直後に ? を付けると最短マッチになる

# --- グループの種類 ---
(abc)           # キャプチャグループ（後から \1 や $1 で参照できる）
(?:abc)         # 非キャプチャグループ（グループ化はするが後方参照はしない）
(?<year>\d{4})  # 名前付きキャプチャグループ（処理系により (?P<year>\d{4}) の場合もある）

# --- 後方参照 ---
(\w)\1          # 直前のキャプチャグループと同じ内容が続く（例: "aa", "bb"）
```

## Notes

- 先読み・後読みは「ゼロ幅アサーション（zero-width assertion）」と呼ばれ、`^`/`$`/`\b` と同じく「その位置に何があるか／ないか」を確認するだけで、マッチした文字列にもキャプチャ結果にも含まれません。同じ位置から続けて次のマッチを探せるのがポイントです。
- 後読み（lookbehind）は処理系によってサポート状況が異なります。Python 標準の `re` は可変長の後読みを許容せず固定長のみ対応、古い JavaScript エンジンでは後読み自体が未対応でした。移植する際は動作確認が必要です。
- **Rust の `regex` クレート（[rg](../commands/rg.md)/ripgrep が既定で使うエンジン）は速度と安全性を優先する設計上、先読み・後読みを一切サポートしていません。** `rg` でどうしても先読み・後読みを使いたい場合は `-P`（`--pcre2`）オプションで PCRE2 エンジンに切り替えます。
- `.` は既定では改行にマッチしません（多くの処理系で `s` フラグ／DOTALLモードを付けると改行にもマッチするようになります）。
- `*`/`+`/`{n,m}` は既定で貪欲（できるだけ長くマッチ）です。直後に `?` を付けると非貪欲（できるだけ短くマッチ）になります。
- 正規表現には方言（フレーバー）があり、構文に差があります: POSIX BRE/ERE, PCRE, ECMAScript(JS), Python `re`, Rust `regex` など。あるツール向けに書いたパターンが別のツールでそのまま動くとは限りません。
